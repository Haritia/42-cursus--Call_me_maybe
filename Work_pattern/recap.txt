Questions de design (à décider toi-même)
1. Quels modèles pydantic ? Au minimum trois :
  - la définition d’une fonction (nom, description, paramètres, retour)
  - un prompt de test
  - un résultat (prompt, name, parameters)
2. Les paramètres : le sujet montre number et string, et mentionne « boolean, etc. ». Comment limites-tu les types acceptés ? Que fais-tu d’un type inconnu ?
3.Gestion des erreurs : faut-il une exception personnalisée pour regrouper toutes les erreurs de lecture ? Où les attrapes-tu : dans chaque fonction ou à un seul endroit (__main__) ?
4. Un prompt invalide parmi cent : tu arrêtes tout, ou tu l’ignores avec un avertissement ? Pèse les deux options par rapport à « jamais de crash ».
5. Sortie : data/output/ n’est pas dans le dépôt, donc il n’existera pas à la correction. Comment le programme s’en sort-il ?
6. Types numériques : le sujet montre "a": 2.0 en sortie, alors que le prompt dit « 2 ». Que vaut json.load pour 2 ? Que doit contenir ton modèle pour un type number ?
